**코드 수정 및 아래 자동 검증과 TestFlight/iPhone 실검증은 구분한다. 실기기 결과는 아직 전부 미검증이다.**

## 기존 처리와 발견한 문제

PC `src/App.tsx`의 종료 버튼은 통계를 확정하고 조건을 충족하면 캐릭터를 PC 컬렉션에 저장했다. React 측정 단계를 종료로 바꾸고, 앞선 작업에서 추가한 이벤트를 Tauri 브리지로 보냈다. 모바일은 이벤트를 받아 저장 후 ACK하고 WS snapshot으로 측정 상태를 복원했다.

1. 획득 재전송 대기열은 Rust 메모리에만 있었다. 휴대폰이 응답하지 않아도 PC UI는 ACK를 기다리지 않았지만, PC 재시작 후 미전달 결과 복구가 없었다.
2. 보상 없는 측정의 최종 결과는 모바일에 전달·저장하지 않았다. PC 최종 결과도 React 메모리에서만 유지됐다.
3. `measuring_stopped`를 측정 ID·순서 확인 없이 적용했다. 과거 결과 재전송의 상태 필드도 새 측정 UI를 바꿀 여지가 있었다.
4. JS 측정 시간은 `performance.now()` 기반 소수 밀리초인데 Rust 입력은 `u64`였다. 실제 값을 전달하면 역직렬화 실패할 수 있었다.
5. 네이티브 송신이 느린 소켓에 쓰기를 기다릴 수 있었다. 측정 종료 관련 broadcast를 별도 스레드로 옮겼다.

## 두 종류의 잠금

- **앱 내부:** 별도의 잠금 PIN/잠금 해제 플래그는 없다. `app/pairing-test.tsx`의 `isMeasuring` 조건이 측정 전용 화면을 선택한다. 카드의 `locked` 스타일은 미획득 카드 표현이며 측정 화면 잠금과 다르다.
- **iPhone 화면 잠금:** OS가 JS·네트워크 처리를 정지시킬 수 있다. 잠금 동안 수신·저장·ACK·진동을 보장하지 않는다. 전경 복귀 시 소켓을 새로 연결하고 현재 snapshot과 미확인 결과를 받는다. 푸시나 백그라운드 지속 실행을 추가하지 않았다.

## 수정 후 실제 흐름

1. PC 측정 시작 시 UUID를 생성한다. 시작/종료 상태와 결과에 같은 `measurementId`를 사용한다. 중복 종료 클릭도 같은 측정을 다시 확정하지 않는다.
2. 종료 시 통계·타임라인·보상 판정·캐릭터 정보를 PC `posture.mobile.measurement-journal.v1`에 동기 저장한다. 보상 없는 측정도 포함한다. 저장 기록에는 PC 출처 ID(`posture.mobile.source-id.v1`)가 포함된다. 이는 앱이 생성하는 로컬 식별자이며 Apple/Expo 계정 식별자가 아니다.
3. PC 화면은 종료 상태로 전환한다. **모바일 응답이나 ACK를 기다리지 않는다.** 별도 송신 루프가 최대 약 2초 안에 기록을 Tauri에 전달한다. 실패하면 재시도한다. 네이티브가 수락하거나 모바일이 ACK해도 PC 기록은 삭제하지 않는다.
4. Rust가 `measurement_completed`를 ACK·재전송 가능한 이벤트로 보낸다. `result`에는 최종 결과 전체가, 캐릭터가 있으면 `payload`와 `result.character`에 포함된다. `eventId/sequence`는 전송 식별자, `result.sourceId/id`는 영속 결과 식별자다. 측정 시간 타입은 소수 밀리초를 허용한다.
5. 모바일이 수신하면 결과와 그 캐릭터를 하나의 AsyncStorage 결과 레코드에 저장하고, 기존 컬렉션 표시용 저장도 갱신한다. **이 두 쓰기가 성공한 뒤** `ack_event(status: "stored")`를 보낸다. 기존의 `received` 표시를 변경했다. 저장 실패하면 ACK하지 않는다.
6. 결과는 `sourceId + id` 기준으로 중복 저장하지 않는다. PC 출처가 다른 기록과 기존 모바일 컬렉션은 삭제하지 않는다. 컬렉션 재전송이 더 오래된 같은 캐릭터 정보를 최신 정보 위에 덮지 않도록 했다.
7. 측정 상태 메시지는 `sequence`를 검사한다. 다른 measurementId의 늦은 stop은 무시한다. 과거의 `measurement_completed`/`acquired_character` 재전송은 현재 측정 상태를 덮지 않는다. 현재 측정과 일치하는 완료만 그 측정을 종료시킨다.
8. 복귀·재연결 시 snapshot으로 현재 측정 상태를 복원한다. 종료 상태면 측정 전용 화면에서 벗어나고, 홈에 최근 측정의 시간·좋은 자세 비율·보상 여부를 표시한다. 결과가 복원되면 캐릭터도 확인할 수 있다. 측정 종료 뒤에는 전경 진동/소리를 멈춘다.
9. 모바일 재실행 시 저장한 결과·캐릭터를 복원한다. PC까지 재시작했다면 PC 기록을 읽어 다시 전송한다. PC port/token은 바뀌므로 새 QR로 재페어링한다.

ACK는 **모바일 영속 저장 성공**을 의미한다. 사용자가 결과 팝업을 읽었다거나 잠금 중 즉시 알림이 표시됐다는 의미는 아니다. AsyncStorage/PC 앱 데이터 자체를 사용자가 삭제하거나 기기 저장소가 고장 난 경우까지 보존을 보장하지 않는다.

PC 저장 실패는 무시하지 않고 오류를 표시하며 해당 결과를 메모리에 남겨 저장을 재시도한다. 오류가 계속되면 앱을 닫기 전에 저장 공간 문제를 해결해야 한다. 저장 실패 상태에서 PC 프로세스를 강제 종료하면 메모리의 결과는 보존할 수 없다.

## 자동 검증

모바일 폴더 `/Users/kyoungpin/Desktop/01_coding/14hack1/vibe-app`:

```sh
npm run lint
npx tsc --noEmit
npm run test:pairing
npm run test:contracts
npx expo export --platform ios --output-dir /tmp/piiin-ios-locked-completion
```

- 링크 cold/warm 변환·포트 검사.
- 캐릭터 저장 전/저장 실패 시 ACK 금지 및 중복 저장 방지.
- 종료 snapshot이 측정 화면 조건을 해제함.
- 새 측정 B 진행 중 늦은 A 종료·결과가 B를 멈추지 않음.
- 보상 없는 결과를 재로드하고 서로 다른 PC 출처를 보존함.
- 결과 저장과 컬렉션 저장 모두 끝날 때까지 완료 ACK를 보내지 않음.
- PC 기록을 휴대폰 응답 없이 저장하고 모듈 재로드 후 다시 전달함. 일시 저장 실패 후 기록 복구.
- PC/모바일 7종 공유 필드·별칭·이미지 해시 비교.

PC 폴더 `/Users/kyoungpin/Desktop/01_coding/14hack1/posture-app`:

```sh
bun run build
cargo check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml --lib pairing::server::tests -- --nocapture
```

실제 loopback HTTP/WS 테스트에서 단절된 수신자에게 보상 없는 A 결과를 대기시킨 뒤 B를 시작하고 재접속했다. snapshot은 B 진행 중이며 재전달 결과는 A임을 확인한다. 저장 ACK 이후 대기열 제거, 분할/합쳐진 ACK 처리, heartbeat 및 disconnect도 검증한다. 테스트는 소수 밀리초 값도 포함한다.

이 테스트의 저장소와 React 훅은 일부 mock을 사용한다. OS의 잠금·스케줄링·네이티브 AsyncStorage와 실제 측정 버튼→카메라→iPhone 흐름은 아래 실기기 테스트로 확인해야 한다.
